# StudyMate 产品落地方案 v2（已与用户确认）

> 状态：方案已确认，进入实现阶段（M1 起）。
> 日期：2026-07-27

## 一、产品定义（最终确认）

StudyMate 是一款**单机桌面复习提醒软件**，核心解决一件事：
**学生上传复习计划文档 → 软件解析出任务清单 → 按艾宾浩斯间隔自动排成"复习课表" → 到点桌面弹窗提醒"下一步该复习什么"。**

### 已确认决策
| 维度 | 决策 |
|---|---|
| 形态 | 桌面 exe，分发给一批学生，各自本地 SQLite，数据互不连通 |
| 登录 | 本地账号（首次设用户名/密码，本地校验；删除微信登录占位与 JWT 双令牌） |
| 核心链路 | 上传文档 → 解析任务清单 → 智能排程（艾宾浩斯）→ 桌面提醒 |
| 输入文件 | 半结构化文档（Word/PDF/txt，如"周一 9:00 数学 第一章"自然语言） |
| 解析策略 | **A 为主 + B 兜底**：约定格式优先解析，解析不出的标黄让用户校正 |
| 提醒方式 | 软件前台运行时弹窗/系统通知（暂不做关机后台提醒） |
| 排程逻辑 | 智能排程：文件只给清单，软件按间隔重复自动铺时间；**忽略文件中的具体时间** |
| 排程起点 | 以"上传日"为首次学习日，之后按间隔自动生成复习任务 |
| 计时 | 保留并改造：**必须关联到具体任务**，记录每个任务耗时 |
| 统计面板 | 需要：今日总时长 / 各科时长分布 / 完成率 |
| 资料库 | 保留"上传资料库"功能（材料管理与复习任务并列） |
| AI 知识库 | **保留真正的 RAG 问答**：上传资料后学生可提问（"这章讲了什么""总结第一章"），软件基于资料调用大模型 API 回答 |
| RAG 接入方式 | 调用 API（OpenAI 兼容协议：通义/智谱/DeepSeek/月之暗面均兼容） |
| API Key 管理 | **学生首次运行时自行填写自己的 key**（设置项存本地，开发者不持有 key、不担账单）；key 存本地配置，不联网上传 |
| 离线边界 | 数据(SQLite)与解析/排程/提醒完全离线；仅 RAG 问答这一步走网络（需 key） |

## 二、对现有代码处置

### 保留 / 复用
- Electron 壳 + 白屏修复（v1.1.2 基线）✅
- 本地 SQLite 数据层 ✅
- 文件上传能力、资料库（material 模块）✅
- `record`（计时）模块 → 改造为关联任务 ✅
- `reminder`（提醒）模块 → 改造为智能排程驱动 ✅
- `task`（任务）模块 → 改造为"解析生成 + 排程生成" ✅

### 删除
- 微信登录全部占位（auth.py 中 `/wechat/*`、`wechat_service.py`）
- JWT 双令牌机制（`utils/jwt_utils.py`、`@login_required` 改为本地 session 校验）
- 手动"建计划/建任务"的复杂 UI → 简化为"上传即生成"

### 改造（RAG 复活为 AI 知识库）
- `rag.py` / `ai_route.py`：**不再是砍掉，改为"AI 知识库问答"模块**
  - 保留资料向量化检索（本地 SQLite 存 chunk + 向量，或轻量本地向量库）
  - 问答走 OpenAI 兼容 API（base_url + api_key 由学生本地设置）
  - 无 key 时前端禁用问答并提示"去设置填写 API Key"

### 新增（工作量主体）
1. **文档解析器**（离线、不依赖联网大模型）
   - 支持：.txt / .md（规则解析）、.docx（python-docx）、.pdf（pdfplumber/PyMuPDF）
   - 抽取：科目、内容描述、出现频次/优先级
   - 约定格式（A 为主）：
     ```
     科目 | 内容 | 优先级(可选)
     数学 | 第一章 函数 | 高
     ```
     或自由文本："周一 9:00 数学 第一章" → 忽略时间，取"数学/第一章"
   - 解析不出的行标黄，用户可在校正页编辑后重新生成
2. **智能排程引擎**（艾宾浩斯）
   - 首次学习日 = 上传日
   - 间隔序列：1、2、4、7、15、30 天（可配置）
   - 为每个任务生成 N 次复习节点，铺到日历
   - 生成"复习课表"数据结构，前端按日/周展示
3. **桌面提醒**
   - 前端轮询 / Electron 定时器检查"临近任务"
   - 任务开始前（默认提前 5 分钟）弹窗 + 系统通知
   - 点击"开始"→ 启动关联计时；点击"稍后"→ 延后；点击"完成"→ 标记完成
4. **统计面板**
   - 今日总时长、各科时长分布（饼/柱）、任务完成率
   - 数据来自 record（关联 task）+ task 完成状态

## 三、数据模型调整（草案）

### Task（改造）
- id, user_id, subject, content, priority
- source: 'parsed' | 'manual'
- first_study_date, total_reviews (计划复习次数)
- status: 'pending' | 'active' | 'done'

### ReviewSchedule（新增）
- id, task_id, review_index (第几次), due_date, done(bool), done_at

### Record（改造，关联任务）
- id, user_id, task_id (FK, 可空), subject, mode, start_at, end_at, duration

### Material（保留）
- 现有结构基本不动

### User（改造）
- 去掉 unionid/微信字段（或保留列但不再使用）
- 本地 username/password（明文 hash 本地存储）

## 四、前端页面结构（草案）
1. 登录/初始化页（首次设账号）
2. 上传页（拖入文档 → 解析预览 → 标黄校正 → 生成任务清单）
3. 复习课表页（日历/周视图，显示每天复习任务）
4. 今日任务页（当天待复习列表 + 开始计时/完成）
5. 资料库页（上传的材料管理 + AI 知识库问答入口）
6. 统计页（时长/分布/完成率）
7. 设置页（间隔序列配置、提醒提前量、**API Key / Base URL 配置**）

## 五、迭代计划（建议）
- **M1**：本地账号（去微信/JWT）+ 上传解析（txt/md + docx）+ 校正页 → 能生成任务清单
- **M2**：艾宾浩斯排程 + 复习课表页 + 今日任务页
- **M3**：桌面提醒弹窗 + 关联计时
- **M4**：统计面板 + 资料库整合（含 AI 知识库 RAG 问答，OpenAI 兼容）+ PDF 支持
- **M5**：打包 v2.0 安装包分发
